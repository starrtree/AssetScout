# Website creative execution and quality review

## Inspect the actual references

Open relevant original demos and inspect their rendered appearance/interactions using supported browser or visual tools. A Sheet description is retrieval evidence, not proof of what the visual looks like. Record when inspection is unavailable; do not invent observations. Respect media rights and platform access.

Extract the transferable principle: contrast, crop, negative space, hierarchy, texture, depth, reading order, transformation or timing. Combine principles around this client's story rather than reproducing a reference site or installing every interesting effect. Translate physical installation/Figma examples into viable web behavior rather than treating them as website components.

## Author a coherent visual system

- State one specific concept rooted in the business/artist, supplied assets and intended audience. Generic adjectives are insufficient.
- Plan the whole visitor journey: opening hook, orientation, proof/portfolio, service understanding, conversion and closing. Each section advances that journey.
- Specify typography roles and scale, grid/gutters, deliberate crops, palette/color behavior, material/light treatment, visual hierarchy and repeated motifs. Use the client's assets centrally; avoid a stock template underneath decorative effects.
- Choose one signature interaction plus a few supporting transitions. Additional visual moments are justified by the narrative, not by novelty alone. Allow ambition when the brand and asset/performance budget support it.
- Specify trigger, element, progression, timing, limits, reset, touch/keyboard behavior and static/reduced-motion fallback for every important mechanic.
- Keep navigation and primary conversion actions understandable throughout. Art should increase interest without making booking, contact or purchase harder.

Three directions must differ in structure and experience, not only palette or labels. Do not automatically recycle Editorial/Liquid/3D templates. Derive each route from the current source context and brand. Carry forward existing user preferences and approved combinations.

## Implement with the smallest capable stack

Use existing project architecture when viable. Prefer proven components/techniques and tune them materially; do not settle for their default appearance. Choose CSS/canvas/one shader/full 3D according to the behavior required, not a blanket prohibition on complexity.

Check exact framework and peer versions, licenses, asset rights, render ownership, SSR/client boundaries and failure paths before adding dependencies. Prototype the riskiest signature interaction early with actual assets. If it performs poorly, adapt the execution while preserving the creative concept. Do not replace a difficult design with generic cards without explanation.

Integrate the effect into responsive layout, content, navigation and working conversion controls. Deliver a complete site experience, not an isolated hero demo. Do not invent client information or silently publish beyond authorization.

## Review what was rendered

Use screenshots and interaction checks through the environment's supported browser tools when available. Inspect at least desktop and a narrow mobile viewport, plus the primary conversion path. Review first screen and full-page continuity; inspect intermediate animation states rather than only a still endpoint.

Assess each dimension against the brief and chosen references:

| Dimension | Passing evidence |
| --- | --- |
| Brand specificity | Concept, assets and visual choices could not be swapped into an unrelated business unchanged. |
| Composition and typography | Intentional hierarchy, crops and spacing; readable copy; no accidental clipping or template repetition. |
| Immersion and motion | Mechanic expresses the concept; pacing supports reading; transitions connect sections coherently. |
| Function and conversion | Real navigation/forms/booking path works; no decorative control masquerades as a working action. |
| Mobile and accessibility | Touch, keyboard, focus, contrast, semantics and reduced motion retain content and action paths. |
| Performance and robustness | Budgeted assets; deferred optional effects; no broken loading, media errors, uncontrolled GPU cost or layout shifts. |

Fix observed weak or failed dimensions before handoff, then recheck affected paths. Do not invent numerical quality scores or call a build award-ready based on a prompt, successful compile or test count. If browser/device testing is blocked, finish available checks and report precisely what remains unverified; follow environment restrictions rather than improvising prohibited browser methods.

Record actual implementation choices and observations. Save a pattern candidate only after a working result exists; promote it after evidence and human review under the existing Motherboard write rules.
